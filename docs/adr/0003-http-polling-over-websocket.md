# 传输用 1 Hz HTTP 轮询，不用 WebSocket

这是个实时仪表盘，直觉上该用 WebSocket 或 SSE 推送。我们仍然选了轮询。

1 Hz 下一个客户端意味着每秒一个几十字节的请求。轮询的实现成本接近零，而 WebSocket 要额外处理握手、心跳、断线重连、半开连接——这些代码没有一行能改善副屏上看到的东西。

轮询还有个副作用是好的：**失联检测是免费的**。请求失败就是失联，不需要额外的超时机制。

它同时让「停更」变得可判：请求成功但 `seq` 不前进，说明服务端活着而采集循环卡住了。这是一条推送式连接不会免费给出的信号——WebSocket 上你分不清「没消息」和「消息没来」。

## 什么时候该换

需要 5 Hz 以上的刷新、或者客户端数量涨到几十个时，轮询的头部开销才值得计较。届时换成 SSE 比 WebSocket 更贴近需求：单向、就是推数据。
